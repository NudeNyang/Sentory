# Sentory 개인정보 및 로컬 데이터 안내

최종 수정일: 2026-07-30

Sentory는 계정, 광고, 분석 도구와 Sentory 전용 서버를 사용하지 않는 로컬
데스크톱 프로그램이다.

## 저장되는 데이터

Sentory는 사용자가 지원 메신저에서 다룬 링크와 사진, 사진에서 로컬 OCR로
인식한 글자와 자동 이름, 즐겨찾기·복사 횟수, 화면 테마·언어·자동 정리 설정 및
오류 진단 기록을 다음 폴더에 저장한다.

```text
%LOCALAPPDATA%\Sentory
```

컴퓨터 간 동기화를 켜지 않으면 데이터베이스와 사진은 사용자의 PC에만
보관된다. 동기화를 켜면 사용자가 직접 선택한 Google Drive·OneDrive·MEGA
등의 로컬 동기화 폴더나 입력한 NAS WebDAV 서버에 사진·링크와 Sentory 동기화
작업이 평문으로 저장된다. 이 작업에는 즐겨찾기, 기기별 복사 횟수, 최근 외부
사용 세션과 자동 즐겨찾기 설정이 포함된다. Sentory는 이 데이터를 NudeNyang의
서버로 전송하지 않는다.

NAS 연결에 쓴 비밀번호는 Windows의 현재 사용자 계정으로 암호화한 값만 로컬
설정에 저장하며 설정 화면으로 다시 보내지 않는다. WebDAV 주소가 HTTP이면
전송 중인 계정 정보와 자료가 암호화되지 않을 수 있으므로 HTTPS 사용을 권장한다.
NAS 서버의 계정 관리, 보관과 외부 공개 범위는 사용자가 선택한 서버 설정을 따른다.

사진 OCR은 앱에 포함된 PP-OCRv5 모바일 모델로 백그라운드에서 처리한다.
원본 사진이나 인식된 글자를 OCR 처리를 위해 외부 서버로 보내지 않는다.

보관함에서 사진을 열면 Windows 사진 앱에 화면 제목과 같은 파일명을 보여주기
위해 `%TEMP%\Sentory\opened-images`에 임시 사본을 만든다. 이 사본도 PC 밖으로
전송하지 않으며, 7일이 지나면 Sentory를 시작할 때 정리한다. 중복 제거와 무결성
확인에 사용하는 원본 사진은 `%LOCALAPPDATA%\Sentory\images`에 SHA-256 파일명으로
계속 보관한다.

## 네트워크 사용

저장된 링크 카드의 제목, 설명, 사이트 아이콘과 대표 이미지를 만들기 위해
해당 링크의 웹사이트에 직접 요청할 수 있다. 이 과정에서 일반적인 웹 요청과
마찬가지로 사용자의 IP 주소 등 연결 정보가 해당 웹사이트에 전달될 수 있다.
미리보기 요청은 시스템 프록시를 사용하지 않고 DNS와 실제 연결 단계에서
로컬·사설 주소를 차단한다. 이 정책 때문에 사설 DNS나 프록시가 필수인 환경에서는
썸네일이 표시되지 않을 수 있지만, 저장한 링크와 링크 열기 기능에는 영향이 없다.

Sentory 자체는 사용 통계, 광고 식별자 또는 저장한 링크·사진을 제작자 서버로
전송하지 않는다.

## 메신저 감지

Sentory는 Windows의 클립보드, 창 정보와 접근성 인터페이스를 사용하여 Discord,
Slack, WhatsApp, Telegram, KakaoTalk, LINE과 WeChat의 지원 채팅 입력 문맥을
확인한다.
Discord와 Slack은 붙여넣기·탐색기 드롭 후보를 실제 발신 메시지와 대조하고,
LINE은 같은 대화의 새 메시지 항목과 명시적 전송 입력을 함께 확인한다. LINE이
메시지 본문을 접근성 값으로 제공하면 URL도 대조하고, 본문을 제공하지 않는
버전에서는 새 메시지 ID만 사용하며 그 본문을 별도로 추출하거나 기록하지 않는다.
Discord 링크 전송 뒤 같은 URL이 5초 동안 보이지 않으면 접근성 메시지 목록을
한 번 새로 찾고 최대 15초까지만 추가 확인한다. 이 재확인도 입력한 전체 메시지를
저장하지 않으며, 클립보드에서 정규화한 URL과 실제 발신 메시지의 URL 일치 여부만
사용한다.
LINE 붙여넣기는 포커스 요소가 실제 메시지 작성기 `AutoSuggestTextArea`와 같은
Runtime ID이고 같은 LINE 프로세스일 때만 후보로 만든다. 왼쪽 대화 검색창
`LcTextField`의 붙여넣기는 읽지 않는다. 후보만 만들어진 상태에서는 저장하지
않으며 실제 전송 증거가 없으면 만료시킨다.
사진을 붙여넣은 직후 같은 LINE 프로세스의 `AlertWindow` 사진 전송창으로
포커스가 이동한 경우에는 클립보드에 실제 사진이 있을 때만 기준점을 허용한다.
사진 전송창이라는 사실만으로 저장하지 않으며 같은 대화의 새 메시지와 명시적
전송 입력 확인은 그대로 필요하다.
빠른 붙여넣기 직후 Enter도 놓치지 않도록 같은 LINE 창의 문맥 해시와 Enter
시각만 메모리에 최대 2분 보존한다. 입력한 키 문자열, 메시지 내용이나 주소는
이 신호 기록에 포함하지 않으며 붙여넣기 이전 또는 다른 창의 Enter는 사용하지
않는다.
WhatsApp은 메시지 원문 대신 제한된 작성기·발신 영역 변화만 비교한다.
Telegram도 메시지 원문이나 접근성 트리를 읽지 않고 검증된 Telegram 창의 제한된
대화 영역을 저해상도 픽셀 지문으로 비교한다. 붙여넣기·드롭 후보, 명시적 Enter
또는 전송 영역 클릭, 전송 뒤 연속된 화면 변화가 모두 확인된 경우에만 저장한다.
WeChat은 검증된 Qt 채팅 작성기와 메시지 항목 ID를 사용하며, 링크 원문은
전송 일치 여부를 판단하는 동안에만 메모리에 둔다. `WeChatAppEx.exe` 같은
미니프로그램 보조 프로세스는 드롭 표면을 구분할 때만 사용하고 대화 내용을
읽는 대상으로 삼지 않는다.
전송되지 않은 초안과 지원 대상이 확실하지 않은 입력은 저장하지 않으며,
다른 앱의 일반 입력 내용을 수집하거나 원격 서버로 전송하지 않는다.

## 데이터 삭제

설정의 데이터 관리 기능에서 즐겨찾기 제외 항목을 삭제하거나 자동 정리를
설정할 수 있다. 모든 데이터를 직접 제거하려면 Sentory를 완전히 종료한 뒤
`%LOCALAPPDATA%\Sentory` 폴더를 삭제한다. Microsoft Store판의 로그, 링크
미리보기와 OCR 모델은 패키지별 로컬 데이터 폴더에 따로 저장되며 앱을 제거하거나
다시 설치할 때 없어져도 자동으로 다시 만들어진다.

GitHub 설치판이나 Microsoft Store판을 제거해도 보관함 DB, 사진, 설정이 들어 있는
`%LOCALAPPDATA%\Sentory`는 자동 삭제하지 않는다. 이는 실수로 보관함을 잃는
일을 막기 위한 동작이다.
