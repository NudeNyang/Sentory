# KakaoTalk 즉시 캡처 구현 결과

검증일: 2026-07-16

검증 환경:

- Windows 11
- KakaoTalk 26.6.0.5208
- .NET SDK 8.0.423

## URL Ctrl+V

저장 조건:

1. 이벤트 당시 전경 프로세스가 `KakaoTalk.exe`
2. 포커스 컨트롤 클래스가 `RICHEDIT50W`
3. 포커스 컨트롤 ID가 `1006`
4. 입력 컨트롤의 루트가 이벤트 당시 전경 채팅창과 일치
5. 같은 루트에 클래스 `EVA_VH_ListControl_Dblclk`, ID `100` 존재
6. 클립보드 시퀀스 번호가 처리 중 바뀌지 않음
7. UIA Value/Text 패턴에서 클립보드 URL과 같은 정규화 URL 확인

실제 결과:

- 카카오톡 개별 채팅 입력창에 붙여넣은 URL 저장 성공
- 전송하지 않음
- `delivery_status = NotObserved`
- `capture_method = KakaoCtrlVUrl`
- `capture_count = 1`
- `share_count = 0`
- `utm_source`와 URL fragment 제거 확인

## 사진 Ctrl+V

카카오톡은 사진을 입력 컨트롤 값에 넣지 않고 별도 확인 창을 만든다.

확인된 구조:

- 새 최상위 창 클래스: `EVA_Window_Dblclk`
- 새 창 owner: 원래 개별 채팅창
- 관찰 크기: 680×800
- 포커스 자식 클래스: `Edit`
- 포커스 자식 컨트롤 ID: `100`

저장 조건:

1. URL과 같은 개별 채팅 입력창 게이트를 먼저 통과
2. 이벤트 당시 클립보드에 이미지 존재
3. PNG 변환 전후 클립보드 시퀀스 번호 유지
4. 같은 KakaoTalk 프로세스에 새 전경 확인 창 생성
5. 확인 창 owner가 원래 개별 채팅창
6. 확인 창과 포커스 자식의 클래스 및 컨트롤 ID 일치

실제 결과:

- 48×32 클립보드 이미지 붙여넣기 후 로컬 PNG 저장 성공
- 카카오톡 확인 창에서 Esc로 취소해 전송하지 않음
- `delivery_status = NotObserved`
- `capture_method = KakaoCtrlVImage`
- SHA-256, PNG 크기, 픽셀 크기 저장 확인
- 저장 파일 존재 확인

## 다른 앱 오탐

별도로 실행한 메모장을 실제 전경 창으로 검증한 뒤 테스트했다.

- 메모장 URL Ctrl+V: DB 이벤트 수 변화 없음
- 메모장 사진 Ctrl+V: DB 이벤트 수 변화 없음

테스트 도구도 전경 전환 성공을 확인하지 못하면 붙여넣기를 실행하지
않도록 수정했다.

## 드래그 앤 드롭

로컬 사진은 Sentory 소유의 임시 드롭 영역을 통해 지원한다. 탐색기에서
파일 드래그를 시작하고 포인터가 검증된 카카오톡 개별 채팅창에 들어오면,
Sentory가 해당 개인 채팅창 전체의 화면 좌표를 따라 보이지 않는 드롭
영역을 표시한다. 영역에서 OLE `FileDrop` 경로를 확인하는 즉시 숨겨
사용자가 시작한 원래 드래그가 아래의 카카오톡 창에 그대로 도착하게 한다.
카카오톡이 네이티브로 사진을 받은 뒤 소유 관계가 확인된 첨부 미리보기
창이 나타나야 묶음 저장한다.

다음 방식은 계속 사용하지 않는다.

- KakaoTalk 창 서브클래싱 또는 DLL 주입
- 탐색기 선택 파일과 마우스 위치를 추측해 결합
- 브라우저 드래그 데이터를 임의 추정

드롭 영역은 탐색기 파일 드래그 중에만 나타나며 검색창, 설정창, 다른 앱,
최소화된 카카오톡 창에는 생성하지 않는다. 드롭하지 않고 취소하거나
지원하지 않는 형식이면 클립보드와 저장소를 변경하지 않는다.

## `+` 파일 선택 업로드

2026-07-27에 카카오톡 개별 채팅창이 소유한 Windows 파일 선택창을 관찰하는
경로를 추가했다. `열기` 버튼이 확인되고 선택창에서 읽은 경로가 실제 존재하는
지원 이미지일 때만 기존 파일 읽기·저장 제한을 적용하며, `KakaoFileDialog`와
원본 파일명을 기록한다. `취소`하거나 PDF·ZIP 등 일반 파일만 선택한 경우는
저장하지 않는다. 카카오톡은 기존 붙여넣기·드롭과 마찬가지로 전송 완료를
접근성 구조에서 확정하지 않으므로 상태는 `NotObserved`를 유지한다.

첫 개발자판 검수에서는 카카오톡 소유 파일 선택창은 찾았지만 Windows가
`열기` WinEvent를 보내지 않았고, 숨겨진 이미지 확장자 때문에 경로도 읽지
못했다. 이후 `열기`·`취소`의 실제 마우스 클릭과 Enter·Esc를 관찰하고,
현재 폴더에서 유일하게 일치하는 지원 이미지 확장자만 복원하도록 수정했다.
메신저 소유가 확인돼 추적 중인 선택창 외의 입력은 기록하지 않는다. 자동
검증은 완료했으며 실제 카카오톡 재검수는 남아 있다.

두 번째 실검수에서는 사진 한 장을 클릭하는 즉시 선택창이 닫히는 경로와,
여러 장을 선택해 `열기`를 누르는 경로 모두 선택 상태를 읽지 못했다. 이를
해결하기 위해 120ms UIA 폴링 외에 Windows 선택·선택 추가·선택 제거·파일명
값 변경 WinEvent에서 MSAA 값을 즉시 누적한다. 단일 클릭 자동 확정은 최근
선택 이벤트와 실제 지원 이미지 경로가 모두 있을 때만 허용하고, 다중 선택은
선택 추가 이벤트와 파일명 컨트롤의 전체 값을 함께 사용한다. 명시적인 취소는
항상 우선한다.
