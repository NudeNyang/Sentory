# WebView2 갤러리 전환 로드맵

결정일: 2026-07-28

현재 상태: 1.5.0 WPF 기준판을 릴리즈했고 `codex/webview2-gallery` 브랜치에서
카드 스크롤 영역의 1단계 WebView2 시제품을 시작했다. 개발자판 명시적 선택일
때만 켜지며, 일반 실행과 공개판은 아직 기존 WPF 갤러리가 기본이다.

## 결정

Windows용 Sentory의 메신저 감지, 사진·링크 저장, SQLite, 클라우드 동기화와
설정은 C#으로 유지한다. 현재 WPF 갤러리는 1.5.0 릴리즈까지 안정된 기준판을
사용하고, 그 다음 개발 단계에서 갤러리 화면만 WebView2로 교체한다.

WebView2는 Sentory 창 내부에 포함한다. 사용자가 Edge나 다른 웹브라우저를 따로
열지 않으며, 갤러리 HTML·CSS·JavaScript도 앱과 함께 로컬로 배포한다. 이 결정은
Windows 갤러리에 대한 것이고 macOS UI 기술 선택은 별도 과제로 남긴다.

## 작업 순서

1. WPF 메모리·스크롤 실험을 최적화 이전 기준판으로 롤백한다. 완료.
2. WeChat Windows 데스크톱 앱의 사진·링크 전송 감지를 추가하고 실제 검수한다. 완료.
3. 현재 기능과 WeChat 지원을 포함한 1.5.0 릴리즈 후보를 검증하고 릴리즈한다. 완료.
4. 별도 브랜치에서 WebView2 갤러리 시제품을 만든다. 1단계 읽기 전용 범위
   가상화와 지연 이미지 로딩 완료.
5. 검색·필터·정렬·복사·즐겨찾기·삭제·상세·선택·다국어·테마를 이식한다.
6. 기존 WPF 갤러리와 기능 및 데이터 호환성을 비교한 뒤 기본 화면을 교체한다.

## 사용자 경험 완료 기준

- 마우스 휠과 스크롤바 손잡이를 빠르게 드래그해도 카드 위치가 프레임 단위로
  자연스럽게 움직이고 이미지 로딩 때문에 이동량이나 입력 반응이 줄지 않는다.
- 전체 보관함 썸네일을 한꺼번에 만들지 않고 현재 화면과 가까운 영역만 로딩한다.
- 자리를 먼저 이동시킨 뒤 사진이 지연 없이 순차적으로 나타나며, 빠르게 지나간
  영역의 불필요한 요청은 취소한다.
- 수백 개 항목에서도 DOM과 디코딩 이미지 수가 가시 범위에 비례한다.
- 갤러리 렌더러가 실패해도 C# 감지·저장·동기화 작업은 계속 동작한다.

## 기술 방향

- C#과 WebView2는 메시지 브리지로 통신하고 모든 삭제·파일 열기·클립보드 작업은
  C#에서 검증한 뒤 실행한다.
- SQLite 전체 500개를 매번 직렬화하지 않고 페이지 또는 가시 범위 단위의 DTO를
  전달한다.
- 목록은 고정 행·열의 가시 범위를 직접 계산해 화면과 위아래 두 줄의 카드만
  DOM에 둔다. 이미지 요청은 동시에 4개만 수행하고 화면 밖으로 나간 요청은
  `AbortController`로 취소한다.
- 원본 파일 경로를 임의의 웹 콘텐츠에 공개하지 않고 앱 전용 로컬 리소스 매핑을
  사용한다.
- Content Security Policy와 허용된 메시지 형식을 적용해 로컬 갤러리 외의 페이지가
  C# 기능을 호출하지 못하게 한다.

## 예상 일정

현재처럼 Codex가 구현하고 사용자가 바로 검수하는 흐름, 하루 6~8시간 기준이다.

- 스크롤·이미지 로딩 시제품: 3~5시간
- 검색·필터가 포함된 사용 가능 개발자판: 1~2일
- 현재 갤러리 기능 이식: 3~5일
- 회귀 검수와 안정화까지: 약 5~7일

1.5.0 이후에는 곧바로 전체 갤러리를 교체하지 않는다. WPF와 WebView2 시제품을
같은 116개·500개·2,000개 보관함으로 비교하고, 자식 프로세스를 합친 메모리와
첫 화면·탭·필터·정렬·스크롤 수치를 확인한 뒤 제품 이식 여부를 결정한다.

## 2026-07-29 1단계 시제품

- 개발 브랜치: `codex/webview2-gallery`
- 활성화: Developer 빌드에서만 `SENTORY_GALLERY_RENDERER=WebView2`
- WPF 유지 범위: 검색, 전체·링크·사진·즐겨찾기 탭, 메신저·날짜 필터, 정렬,
  상태 표시, 설정, 상세창과 모든 C#/SQLite 처리
- WebView2 범위: 카드 배치, 스크롤, 읽기 전용 카드 문구, 순차 썸네일 표시
- 안전장치: 일반 실행 WPF 기본, 초기화 실패 시 WPF 폴백, CSP, 외부 탐색 차단,
  최대 범위 120개, 이미지 동시 처리 4개
- 배포: 웹 자산을 실행 파일에 내장하고 `%LOCALAPPDATA%\Sentory\cache` 아래에
  펼쳐 기존 단일 실행 파일 휴대용 구조를 유지

실제 118개 보관함에서 WebView2 클라이언트가 준비된 뒤 첫 화면 30개만 요청했다.
다만 10초 후 한 번 측정한 전체 작업 집합은 WPF 328.1MB에서 WebView2 769.3MB로
늘었다. Chromium 기본 프로세스 비용이 포함된 결과라 WebView2를 기본값으로
바꾸기 전에 500개·2,000개 보관함의 증가 폭과 장시간 스크롤 뒤 회수 여부를
반드시 비교해야 한다.

다음 단계는 검색·탭·필터·정렬 전환을 반복해 범위 초기화와 스크롤 위치가 정확한지
검수하고, 카드 클릭·복사·즐겨찾기·삭제를 C# 명령 브리지로 한 기능씩 옮기는
것이다. 현재 저장소 조회는 최근 500개를 C#에 읽는 기존 구조를 유지하므로,
2,000개 이상을 실제 표시하는 SQL 페이지 조회는 기능 이식 뒤 별도 단계로 진행한다.
