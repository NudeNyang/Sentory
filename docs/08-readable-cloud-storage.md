# 클라우드에서 읽을 수 있는 평문 저장 형식

상태: 저장·자동 이전·Google Drive PC/웹 검증 완료, 모바일 사용자 검수 전

## 제품 결정

Sentory는 하나의 보관함을 여러 컴퓨터에서 공유한다. 개인·업무 보관함을
분리하거나 Sentory 자체 종단간 암호화를 제공하지 않는다. 사진과 링크는
Google Drive·OneDrive의 PC·웹·모바일 앱에서 사용자가 직접 보고 내려받고
공유할 수 있는 평문 형식으로 저장한다.

클라우드 계정과 선택한 폴더에 접근할 수 있는 사람은 내용을 볼 수 있다.
설정 화면은 이 사실을 기능 활성화 전에 명확히 안내한다.

새로 동기화를 시작할 때는 Windows에서 사용할 수 있는 OneDrive 사용자 폴더,
Google Drive의 `My Drive`, Dropbox의 개인·업무 폴더와 기존 MEGA 기본 폴더를
찾고, 선택한 클라우드 바로 아래에 `Sentory` 전용 폴더를 만든다. 사용자가
파일 시스템 경로를 직접 정하는 과정은 기본 흐름에서 제외한다. 공급자가 여러
개면 클라우드 이름만 선택한다. 설정 카드 맨 아래의 `폴더 선택`은 항상 제공해
사용자 지정 MEGA 위치와 다른 클라우드 데스크톱 앱의 동기화 폴더도 수동으로
연결할 수 있게 한다.

이 자동 설정은 `%LOCALAPPDATA%\Sentory`의 SQLite 데이터베이스나 기기별
설정·캐시를 클라우드에 등록하는 기능이 아니다. 로컬 원본 저장소는 컴퓨터마다
분리하고, 검증된 사진·링크와 동기화 작업만 전용 폴더로 내보낸다. 기존에 사용
중인 동기화 경로도 사용자 동작 없이 새 위치로 바꾸지 않는다.

## v2 폴더 구조

자동 생성하거나 사용자가 설정에서 선택한 전용 폴더 바로 아래에 다음 구조를
만든다.

```text
<선택한 폴더>
├─ Photos
│  └─ <sha256>.<원본 확장자>
├─ Links
│  └─ <연도>
│     └─ <월>
│        └─ <날짜-시간>_<도메인>_<작업 ID>.txt
└─ .sentory
   └─ v2
      ├─ objects
      │  └─ devices
      └─ temporary
```

사진 파일명은 콘텐츠 SHA-256과 검증된 원본 확장자로 구성한다. 같은 사진은
기기와 원본 파일명에 관계없이 한 파일만 사용하며 Google Drive·OneDrive가
일반 사진으로 인식한다. 사진 바이트를 다시 인코딩하지 않는다.

링크 파일은 UTF-8 평문이며 제목이 아직 준비되지 않아도 즉시 생성할 수 있는
주소, 도메인, 저장 시각과 출처를 포함한다. 링크 작업 ID를 파일명에 포함해
여러 기기의 동시 저장이 서로를 덮어쓰지 않게 한다. 링크 파일의 Google Drive
웹 열기·다운로드·공유 진입은 확인했다. 실제 모바일 시스템 공유 대상까지
전달되는지는 Android·iOS 앱에서 사용자 검수한다.

`.sentory/v2`에는 기기별 불변 작업, 순번과 체크포인트용 객체만 둔다. 이
정보도 암호화하지 않지만 사용자가 직접 편집하거나 공유할 콘텐츠는 아니다.
작업 객체는 기존의 길이·SHA-256 봉투를 유지해 클라우드 앱이 복사 중인 파일을
완성된 변경으로 오인하지 않게 한다.

## 쓰기와 수신 순서

사진은 로컬 보관함 트랜잭션이 끝난 뒤 임시 파일에 모두 쓰고 SHA-256을
검증한 다음 `Photos`의 최종 경로로 원자 이동한다. 사진 파일이 준비된 뒤에만
해당 항목 작업을 `.sentory/v2`에 공개한다.

링크는 최종 UTF-8 텍스트 파일을 먼저 원자적으로 공개하고 작업 객체를 나중에
공개한다. 중간 종료로 콘텐츠만 먼저 생기면 같은 작업 재시도가 동일 내용을
확인하고 이어서 작업 객체를 게시한다.

받는 기기는 작업 객체의 크기·해시·순번을 검증한다. 사진 작업은 평문 사진의
크기와 SHA-256을 다시 확인한 뒤 로컬 보관함에 반영한다. 파일이 아직 없거나
복사 중이면 손상으로 확정하지 않고 다음 주기에 재시도한다.

받는 앱보다 새 버전에서 추가된 메신저 출처·캡처 방식·전송 상태가 작업에
포함돼도 저장소 손상으로 취급하지 않는다. 해당 항목만 `Pending`으로 보류하고
이미 지원하는 항목과 삭제는 계속 처리하며, 앱 업데이트 뒤 자동으로 다시
투영한다. 실제 본문·파일 크기·SHA-256 불일치는 계속 손상으로 차단한다.

## v1에서 v2로 이전

현재 실제 클라우드 폴더의 `Sentory Sync/v1`은 자동으로 삭제하거나 덮어쓰지
않는다. 업그레이드한 기기는 먼저 마지막 v1 수신을 실행한 뒤 로컬 보관함의
현재 URL·사진 전체를 v2의 새 기기 ID와 저널로 다시 내보낸다.

이전은 다음 조건을 만족해야 한다.

1. v2 초기화와 재내보내기는 여러 번 실행해도 같은 결과를 만든다.
2. 중간 종료 뒤 다음 실행에서 남은 항목부터 계속한다.
3. 사진 수·링크 수·사진 총 바이트와 SHA-256을 이전 전후로 대조한다.
4. v2 검증이 끝나도 v1은 사용자가 별도로 정리하기 전까지 보존한다.
5. 이전 중에는 구형·신형 사진이 함께 있어 일시적으로 추가 용량이 필요하다고
   설정에서 안내한다.

v2가 안정되기 전에는 실제 폴더와 별도의 테스트 폴더에서 먼저 검수한다.
기존 v1 정리는 사용자 검수가 끝난 후 별도 작업으로 진행한다.

## 상태와 즉시성

새 캡처는 로컬 DB 저장 직후 동기화 작업자를 깨운다. 설정의 `최근 동기화
완료`는 Sentory가 선택한 로컬 클라우드 폴더에 파일을 안전하게 썼다는 뜻이다.
데스크톱 클라우드 앱이 서버와 모바일까지 전송을 마친 시점은 직접 API 연동
전에는 Sentory가 보장하지 않는다.

## 검증 기준

- 사진 원본 바이트와 `Photos` 파일이 일치한다.
- Google Drive·OneDrive PC와 웹에서 사진 썸네일·전체 미리보기가 열린다.
- Android 또는 iOS 앱에서 사진 다운로드와 시스템 공유가 가능하다.
- 링크 파일은 모바일에서 주소를 확인하고 복사할 수 있다.
- A에서 만든 링크·사진이 B에 정확히 한 번 나타난다.
- 같은 사진은 클라우드에 한 번만 존재한다.
- 부분 파일·손상·순번 누락·앱 종료·재시작을 안전하게 처리한다.
- 기존 v1 객체는 검수 기간 동안 바이트 단위로 보존된다.

## 구현 브랜치

`codex/cloud-sync-readable-storage`에서 저장 규약, v2 저장 계층, 자동 이전,
설정 UI, 테스트와 개발자판 교체를 구현했다. 이후 실제 두 컴퓨터 검수에서
발견한 삭제 재생성 문제를 해결하기 위해 URL·사진 삭제 tombstone과 평문 파일
제거까지 같은 브랜치에 포함했다. 즐겨찾기·복사 횟수·최근 외부 사용 세션과
자동 즐겨찾기 설정도 숨김 `.sentory` 작업으로 동기화하며, 복원 UI와 묶음
충돌 정책은 이후 단계로 남긴다.

현재 소스에는 표준 사진·UTF-8 링크를 원자적으로 쓰는
`ReadableFolderSyncObjectStore`, v1 마지막 수신과 재개 가능한 저널 전환을
담당하는 `SyncStorageMigrationService`, 앱 시작·캡처·30초 주기의 v2 런타임
연결이 들어가 있다. 삭제 작업을 게시하면 `Photos`의 해당 SHA-256 파일 또는
같은 정규화 URL을 담은 `Links` 텍스트를 제거하고, `.sentory`의 삭제 기록은
과거 추가 작업의 재생성을 막기 위해 유지한다.

사용 메타데이터는 평문 사진·링크 파일을 복제하지 않는다. 각 기기의 누적
복사 횟수, 최근 30일의 6시간 단위 외부 사용 세션, 즐겨찾기 변경 시각과 자동
즐겨찾기 설정을 작은 작업 JSON에 기록한다. 복사 횟수는 기기별 절대 누적값의
최댓값을 보존한 뒤 합산하고, 즐겨찾기와 설정은 가장 최근 변경을 적용한다.
삭제 기록이 있는 항목에는 뒤늦게 도착한 메타데이터를 적용하지 않는다.

자동 즐겨찾기는 기본으로 켜져 있으며 반복 사용 기준은 3회다. 이전 버전의
손대지 않은 `꺼짐·3회·변경 시각 없음` 설정은 로드할 때 새 기본값으로 이전한다.
사용자가 직접 끈 설정처럼 변경 시각이 있는 값은 그대로 보존한다. 새 기본값으로
이전된 값은 로컬 사용자 변경으로 게시하지 않으므로, 다른 컴퓨터에서 명시적으로
선택한 기준이나 켜짐·꺼짐 상태를 덮어쓰지 않는다.

2026-07-26에 실제 Google Drive 동기화 폴더를 이전했다. 기존 v1 59개 파일의
집계 SHA-256은 이전 전후 같았고, v2에는 현재 보관함 기준 사진 21개와 링크
16개가 생성됐다. 사진 21개의 내용 해시가 모두 파일명과 일치하고 부분 파일은
없었다. Google Drive 웹의 `컴퓨터/내 컴퓨터/Sentory-googleDrive`에서 사진
미리보기와 링크 본문, 두 형식의 다운로드·공유 버튼을 확인했다. 사용자 검수
순서는 `docs/09-readable-cloud-storage-qa.md`에 기록한다.
