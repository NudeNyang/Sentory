# Sentory 2.0.8

Sentory 2.0.8에서는 업데이트 뒤 자동 실행이 켜져 있는데도 Windows를 다시 시작하면 앱이 뜨지 않던 문제를 고쳤습니다.

## 자동 실행 등록 복구

Sentory를 다른 폴더로 옮기거나 새 버전으로 교체하면 Windows 시작 프로그램에 예전 실행 경로가 남을 수 있습니다. 이때 설정 화면에는 자동 실행이 켜진 것으로 보이지만, 로그인할 때는 앱이 실행되지 않았습니다.

이제 앱을 시작할 때 저장된 설정과 Windows의 실제 등록 상태를 함께 확인합니다. 자동 실행이 켜져 있다면 등록 항목이 없거나 경로가 오래됐을 때 현재 `Sentory.exe` 경로로 바로 고칩니다.

Windows 설정의 시작 앱 화면에서 Sentory를 직접 껐다면 그 선택은 건드리지 않습니다. 다시 쓰고 싶을 때 Sentory 안에서 자동 실행을 켜면 차단 기록을 지우고 현재 경로로 등록합니다.

## 로그인 직후 실행

로그인 직후에는 Explorer와 작업표시줄이 아직 준비되지 않아 트레이 아이콘이나 최소화된 창이 나타나지 않을 때가 있었습니다. 자동 실행으로 열린 Sentory는 작업표시줄이 준비된 뒤 트레이와 창을 만듭니다. 평소 직접 실행할 때의 속도에는 영향을 주지 않습니다.

기존 보관함과 설정은 그대로 유지됩니다. Microsoft Store판은 이전과 같이 Windows `StartupTask`를 사용하며 GitHub 업데이트 기능은 들어가지 않습니다.

## 다운로드

| 사용 환경 | 설치형 | 포터블 |
| --- | --- | --- |
| Intel·AMD Windows PC | `Sentory-win-x64-setup.exe` | `Sentory-win-x64-portable.zip` |
| Windows on ARM PC | `Sentory-win-arm64-setup.exe` | `Sentory-win-arm64-portable.zip` |

2.0.7 GitHub판에서는 앱 안에서 2.0.8 업데이트를 확인할 수 있습니다. GitHub Release에 올린 파일은 아직 코드 서명이 없어 Windows에서 알 수 없는 게시자 또는 SmartScreen 경고가 나올 수 있습니다. 공식 Release에서 받은 파일인지 확인하고, 필요하면 함께 제공되는 `.sha256` 파일과 비교해 주세요.

## English

Sentory 2.0.8 fixes Windows startup registration after an update or folder move. When startup is enabled, Sentory now repairs a missing or outdated `Run` entry with the current executable path. A manual block in Windows Startup Apps is still respected.

Login launches also wait briefly for Explorer and the taskbar before creating the minimized window and tray icon. Regular launches are unaffected. Microsoft Store builds continue to use `StartupTask` and do not include the GitHub updater.
