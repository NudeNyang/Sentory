# Sentory 1.1.2

Sentory 1.1.2에서는 Discord에 붙여넣어 보낸 사진이 가끔 보관함에서 빠지던
문제를 고쳤습니다. 진단판의 로그가 기존 사용자 폴더에 섞이던 문제도 함께
정리했습니다.

## Discord 사진 감지

- Ctrl+V로 사진을 붙여넣고 Enter를 누른 직후에는 Discord 접근성 트리가 다시
  만들어지면서 메시지 목록이나 렌더러 접근성 루트가 잠깐 사라질 수 있습니다.
- 이전 버전은 이때 한 번만 확인하고 감지를 끝냈습니다. 1.1.2부터는 Enter 전송이
  확인된 후보에 한해 접근성 대상을 최대 3번 다시 찾습니다.
- 다시 찾은 뒤에도 저장 조건은 바뀌지 않습니다. URL은 전송된 메시지와 일치해야
  하고 사진은 본인이 보낸 이미지 첨부 표식이 있어야 저장합니다.

## 진단 데이터 분리

- `SENTORY_DATA_DIR`를 지정하면 데이터베이스, 설정, 이미지, 캐시와 Discord 추적
  로그를 같은 진단 폴더에 저장합니다.
- 접근성 워커에서 예외가 나면 메시지 원문이나 전체 스택은 남기지 않습니다.
  로그에는 예외 형식, 발생 메서드와 HRESULT만 기록합니다.

## 사진을 열 때 보이는 이름

- 원본 사진은 중복 제거와 무결성 확인을 위해 SHA-256 파일명으로 보관합니다.
- 보관함에서 사진을 열면 화면 제목과 같은 이름의 임시 사본을 Windows 사진 앱에
  넘깁니다. 기존 사진에도 적용되며, 7일이 지난 사본은 Sentory를 시작할 때
  정리합니다.
- 빈 보관함 안내 문구는 "메신저에 URL이나 사진을 붙여넣어 보세요."로
  바꿨습니다.

## 다운로드

대부분의 Windows PC에서는 `Sentory-win-x64-setup.exe`를 받으시면 됩니다.
설치하지 않고 사용하려면 `Sentory-win-x64-portable.zip`을 완전히 푼 뒤
`Sentory.exe`를 실행해 주세요. Windows on ARM 사용자는 이름에 `arm64`가
포함된 파일을 선택해 주세요.

현재 파일에는 코드 서명이 적용되지 않았습니다. Windows에서 알 수 없는 게시자나
SmartScreen 경고가 나타날 수 있으므로 공식 Release에서 받은 파일인지 확인하고,
필요하면 함께 제공되는 `.sha256` 파일과 대조해 주세요.

이 Release의 실행 파일에 대응하는 소스는 `Sentory-1.1.2-source.zip`과
`v1.1.2` 태그에서 받을 수 있습니다.

## 알려진 제한 사항

- Discord의 `+` 버튼을 이용한 파일 선택 업로드는 아직 감지를 보장하지 않습니다.
  사진은 채팅 입력창에 Ctrl+V로 붙여넣은 뒤 전송해 주세요.
- Discord 또는 카카오톡의 화면 구조가 바뀌면 감지가 잠시 멈출 수 있습니다.
- ARM64 패키지는 실제 Windows on ARM 장치에서 최종 검수가 남아 있습니다.
- 실행 파일과 설치 프로그램에는 코드 서명이 적용되지 않았습니다.

## English

Sentory 1.1.2 reduces intermittent misses when saving images pasted and sent in
Discord. It also keeps diagnostic trace logs inside the selected diagnostic data
directory instead of mixing them with the regular user profile.

### Discord image detection

- Discord may briefly rebuild its accessibility tree immediately after a pasted image
  is sent, making the message list or renderer accessibility root unavailable.
- After an explicit Enter send, Sentory now retries these transient targets up to three
  times.
- Existing confirmation gates remain unchanged. A URL must match the sent message, and
  an image must still expose the marker for an attachment sent by the current user.

### Diagnostic isolation

- When `SENTORY_DATA_DIR` is set, the database, settings, images, caches, and Discord
  trace log all use that diagnostic directory.
- Worker exception signals record only the exception type, target method, and HRESULT.
  Message content and full stack traces are not logged.

### Image names when opening photos

- Original image files keep their SHA-256 names for deduplication and integrity checks.
- When an image is opened from the library, Sentory gives Windows Photos a temporary
  copy whose file name matches the title shown in the library. This also works for
  existing images, and copies older than 7 days are cleaned up when Sentory starts.
- The empty-library hint now asks users to paste a URL or photo into a messenger.

Most Windows PCs should use `Sentory-win-x64-setup.exe`. Use the portable ZIP if you
prefer not to install the app, or an `arm64` package on Windows on ARM. The binaries
are not code-signed, so Windows may show an Unknown Publisher or SmartScreen warning.

Discord's `+` file-picker upload is not a guaranteed detection path. Paste images into
the chat input with Ctrl+V and send them. Detection may also stop temporarily if
Discord or KakaoTalk changes its interface. Final testing on a physical Windows on ARM
device is still pending.
