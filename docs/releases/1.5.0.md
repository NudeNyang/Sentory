# Sentory 1.5.0

Sentory 1.5.0은 지원 메신저를 Discord와 카카오톡에서 Slack, WhatsApp,
Telegram, LINE, WeChat까지 넓힌 버전입니다. 빠르게 사진을 놓고 보내거나 큰
파일을 연달아 전송할 때 생기던 누락을 메신저 공통 경로부터 다시 다듬었고,
컴퓨터끼리 보관함을 맞추는 클라우드 폴더 동기화도 추가했습니다. 자료가 많은
보관함은 첫 화면과 필터 반응을 먼저 보여 주고 썸네일을 뒤에서 채우도록 바꿨습니다.

## 새로 지원하는 메신저

- Slack 데스크톱 앱에서 붙여넣거나 탐색기에서 드롭한 링크와 사진을 실제로
  전송한 뒤 저장합니다. 첨부를 취소하거나 다른 입력란에 놓은 내용은 제외합니다.
- WhatsApp 데스크톱 앱의 붙여넣기와 사진 드롭을 지원합니다. 붙여넣자마자
  Enter를 누르거나, 사진 등록보다 전송 버튼 입력이 먼저 들어오는 경우도 같은
  전송으로 이어서 확인합니다.
- Telegram Desktop은 붙여넣기와 사진 드롭 전후의 화면 변화와 명시적인 전송
  입력을 함께 확인합니다. 미리보기만 열었다 닫거나 전송하지 않은 사진은
  보관하지 않습니다.
- LINE은 링크·사진 붙여넣기와 탐색기 사진 드롭을 지원합니다. 실제 채팅과
  작성기, 사진 전송창을 구분해 검색창이나 다른 대화에서 일어난 입력을
  가져오지 않습니다.
- WeChat Windows 데스크톱 앱에서 링크·사진 붙여넣기와 탐색기 사진 드롭을
  지원합니다. `Weixin.exe`와 이전 `WeChat.exe`는 인식하되 미니프로그램 보조
  프로세스는 대화 확인에 사용하지 않습니다.
- 새 메신저는 설정에서 따로 끄고 켤 수 있으며 보관함 필터, 카드 출처, 상세
  화면과 한국어·영어·일본어·중국어 상태 문구에도 함께 표시됩니다.

## 빠른 드롭과 연속 전송

- Discord·Slack·카카오톡 위에 있던 투명 드롭 창을 없앴습니다. 이제 메신저가
  처음부터 원래 드롭을 직접 받으므로 사진을 놓을 때 Sentory 때문에 한 번 더
  기다릴 필요가 없습니다.
- 일곱 메신저가 같은 탐색기 드래그를 각각 읽다가 뒤쪽 감지기가 시작점을
  놓치던 경합을 공용 드래그 세션으로 정리했습니다. 저수준 포인터 기록과 실제
  해제 위치를 함께 보존해 16ms 감시 사이에 끝난 빠른 드롭도 복구합니다.
- 큰 사진을 올리는 동안 다음 사진을 보내거나 같은 사진과 겹치는 묶음을 연달아
  보내도 별도 후보로 유지합니다. 같은 대화에 같은 파일이 500ms 안에 두 번
  등록된 경우만 한 드롭의 중복으로 처리합니다.
- LINE·WeChat·Slack·WhatsApp·Telegram은 한 번의 전송 입력을 가장 최근의
  미처리 사진 하나에만 연결합니다. Discord는 한 메시지에 첨부한 여러 사진을
  묶는 기존 동작을 유지합니다.
- LINE 사진창이 원래 채팅창을 가리거나 업로드가 늦어지는 경우, 다음 드래그가
  바로 시작되는 경우, 전송 버튼 입력이 후보 등록보다 앞선 경우를 각각
  보완했습니다. WeChat 보조 업로드 창과 WhatsApp의 빠른 전송도 같은 공통
  경계를 사용합니다.
- Telegram과 LINE은 드롭만 했다는 이유로 저장하지 않습니다. 전송 입력과 실제
  결과를 확인하며, 초안 취소와 다른 앱에 놓은 사진은 만료시킵니다.

## 컴퓨터 간 동기화

- OneDrive, Google Drive, Dropbox, MEGA의 로컬 동기화 폴더를 찾아 보여 주며,
  원하는 폴더를 직접 선택할 수도 있습니다. 연결 전에는 한글 파일 생성·읽기·
  이름 변경·삭제가 가능한 위치인지 검사합니다.
- 사진은 `Photos`에 일반 이미지 파일로, 링크는 `Links/<연도>/<월>`에 읽을 수
  있는 TXT로 저장합니다. 다른 PC나 모바일의 클라우드 앱에서도 사진을 열거나
  링크 내용을 확인할 수 있습니다.
- 사진·링크 추가와 삭제, 즐겨찾기, 복사 횟수, 자동 즐겨찾기 설정을 Windows
  컴퓨터끼리 양방향으로 맞춥니다. 한 컴퓨터가 꺼져 있어도 다음 연결에서 밀린
  변경을 이어받습니다.
- 클라우드의 Sentory 폴더를 지웠거나 저장소 식별자가 달라졌다면 로컬 보관함은
  남겨 두고 새 저장소 세대로 다시 게시합니다. 정상 삭제 기록은 함께 옮겨 다른
  컴퓨터의 오래된 항목이 되살아나지 않게 했습니다.
- 기기 연결을 복구할 때 복사 횟수가 다시 합산돼 두 배씩 커지던 문제와, 설정을
  닫을 때 새 동기화 경로가 예전 값으로 돌아가던 문제를 고쳤습니다.
- 구버전이 모르는 메신저 항목을 받더라도 해당 항목만 보류하고, 이미 이해하는
  사진·링크와 삭제 작업은 계속 처리합니다.

## 보관함과 설정

- 전체·사진·링크·즐겨찾기 탭과 메신저 필터·정렬은 남아 있는 카드 컨테이너를
  재사용합니다. 변경이 많을 때는 컬렉션 알림을 한 번으로 합쳐 WPF가 같은 화면을
  수십 번 다시 배치하지 않게 했습니다.
- 384px 카드 썸네일을 디스크에 만들어 다시 사용합니다. 카드 위치와 문구를 먼저
  바꾼 뒤 이미지를 저우선순위 작업에서 차례로 표시하므로 첫 화면이나 필터 입력이
  원본 사진 디코딩을 기다리지 않습니다.
- 화면 언어를 바꾸면 공용 번역 리소스를 한 번만 교체합니다. 현재 화면은 선택
  직후 바뀌고, 화면 밖 카드만 24개씩 나눠 갱신합니다. Windows 언어를 따르는
  `Auto` 항목도 추가했습니다.
- 선택 모드에서 포인터를 보관함 위나 아래 가장자리에 두면 천천히 자동
  스크롤합니다. 드래그 중 마우스 휠도 함께 쓸 수 있고 화면 밖으로 지나간 카드도
  처음부터 현재 위치까지 선택 범위에 남습니다.
- 메신저 필터는 과거의 모든 전송 이력이 아니라 카드에 표시된 마지막 저장
  메신저를 기준으로 삼습니다. 날짜가 명확한 사진 파일명은 메타데이터나 OCR보다
  제목으로 먼저 사용합니다.
- 메신저 설정은 상태 문구를 유지한 한 줄 스위치 목록으로 정리했습니다. 자동
  즐겨찾기는 새 설치에서 기본으로 켜지고 같은 항목을 세 번 사용하면 적용됩니다.
- 소개 문구를 `이야기 속, 흩어진 순간들을 한 곳에`로 바꾸고 앱 정보의
  `NudeNyang` 표시에 제작자 X 프로필 링크를 연결했습니다. 전송이 확인된 카드의
  상태 문구는 모든 메신저에서 `전송 시 저장됨`으로 통일했습니다.

## 안정성과 반응 속도

- Discord 접근성 작업자가 오래된 화면에 고정되면 Discord를 재시작하지 않고
  작업자만 한 번 새로 만듭니다. 화면 공유 전체 화면에서 메시지 목록에
  `OFFSCREEN` 상태가 붙어도 정상 목록이라면 연결 준비를 마칩니다.
- Discord가 꺼져 있을 때는 불필요한 `연결 준비 중` 배너를 숨깁니다. 전송한
  링크가 접근성 목록에 늦게 나타나는 경우에는 새 목록을 찾아 최대 15초까지
  실제 발신 메시지를 확인합니다.
- LINE의 유휴 접근성 갱신을 UI 스레드 밖으로 옮겼습니다. 확인창과 라이선스도
  네이티브 창 전체를 막지 않는 방식으로 바꿔 작업표시줄에서 Sentory를 반복해
  열 때 나던 Windows 경고음과 복원 지연을 줄였습니다.
- 사진 카드와 링크 미리보기는 384px, 사이트 아이콘은 64px, 상세 이미지는
  480px로 나눠 읽습니다. 상세 이미지는 상세창을 열기 전까지 디코딩하지 않습니다.
- 첫 클라우드 동기화는 화면이 뜬 뒤 8초에 시작합니다. 언어·검색·필터·정렬·탭
  조작 중에는 진행 중인 폴더 읽기를 중단하고 입력이 2초간 없을 때 다시 시작해
  보관함 조작을 우선합니다.
- 실제 116개 보관함과 428.9MB 원본 사진으로 탭 처리 약 58~59ms, 한 번 표시한
  탭의 화면 완료 약 264~360ms를 확인했습니다. Release 구성의 자동 테스트
  869개도 통과했습니다.
- 개발자판 게시 때 QA VM의 실행 파일이 자동으로 같은 빌드로 교체되며, 종료
  확인·자체 점검·SHA-256 일치까지 마쳐야 게시를 성공으로 처리하도록 배포 절차를
  강화했습니다.

## 다운로드

대부분의 Windows PC에서는 `Sentory-win-x64-setup.exe`를 받으면 됩니다. 설치하지
않고 사용하려면 `Sentory-win-x64-portable.zip`을 완전히 푼 뒤 `Sentory.exe`를
실행해 주세요. Windows on ARM 사용자는 이름에 `arm64`가 포함된 파일을 선택하면
됩니다.

현재 파일에는 코드 서명이 적용되지 않았습니다. Windows에서 알 수 없는 게시자나
SmartScreen 경고가 나타날 수 있습니다. 공식 Release에서 받은 파일인지 확인하고,
필요하면 함께 제공되는 `.sha256` 파일과 대조해 주세요.

이 Release의 실행 파일에 대응하는 소스는 `Sentory-1.5.0-source.zip`과
`v1.5.0` 태그에서 받을 수 있습니다.

## 알려진 제한 사항

- 메신저의 `+` 버튼으로 파일 선택창을 여는 업로드는 감지를 보장하지 않습니다.
  사진은 채팅 입력창에 붙여넣거나 탐색기에서 드롭한 뒤 전송해 주세요.
- 지원 메신저가 화면 구조를 바꾸면 감지가 잠시 멈출 수 있습니다.
- 자료가 많은 WPF 보관함의 첫 썸네일 생성은 시간이 걸릴 수 있습니다. 카드와
  조작 결과를 먼저 표시하고 이미지는 차례로 채웁니다.
- ARM64 패키지는 실제 Windows on ARM 장치에서 최종 검수가 남아 있습니다.
- 실행 파일과 설치 프로그램에는 코드 서명이 적용되지 않았습니다.

## English

Sentory 1.5.0 expands messenger support from Discord and KakaoTalk to Slack,
WhatsApp, Telegram, LINE, and WeChat. It also adds folder-based cloud sync between
computers, hardens rapid and consecutive image sends, and reduces startup and gallery
interaction stalls on larger libraries.

### New messenger support

- Slack, WhatsApp, Telegram, LINE, and WeChat desktop apps now support confirmed link
  and image sends from paste or Explorer drag-and-drop where the client allows it.
- Drafts, canceled previews, unrelated input fields, other conversations, and drops
  that are never sent are rejected.
- Each messenger has its own Settings switch, library filter, card source, detail
  label, and localized status text.

### Rapid and consecutive sends

- Discord, Slack, and KakaoTalk no longer receive drops through a transparent Sentory
  overlay. The messenger handles the original drag directly.
- A shared pointer snapshot lets all seven detectors recover very quick Explorer drags
  even when a 16ms polling boundary misses the initial mouse-down.
- Consecutive large uploads, repeated images, overlapping batches, delayed preview
  windows, and send input that arrives before candidate registration are handled as
  separate sends. Only a duplicate registration of the same payload in the same chat
  within 500ms is collapsed.
- LINE, WeChat, Slack, WhatsApp, and Telegram consume one send signal for one pending
  candidate. Discord keeps its explicit multi-attachment batch behavior.

### Sync between computers

- Sentory can use a local OneDrive, Google Drive, Dropbox, or MEGA folder, or a folder
  selected manually. The destination is tested for the required file operations before
  it is connected.
- Photos are published as regular image files under `Photos`; links are readable TXT
  files under `Links/<year>/<month>`.
- Adds, deletes, favorites, copy counts, and automatic-favorite settings sync in both
  directions between Windows computers. Offline changes continue on the next sync.
- Deleted or replaced cloud stores are rebuilt from the local library without reviving
  items that have a valid deletion record. Device reconnection no longer multiplies
  copy counts, and older Sentory versions can skip only unknown messenger records while
  continuing compatible work.

### Library and settings

- Tabs, messenger filters, and sorting reuse existing card containers where practical,
  while larger changes are applied as one collection reset.
- A persistent 384px JPEG card cache and a serialized low-priority loader keep original
  image decoding away from the UI thread. Layout and text appear before thumbnails are
  filled in.
- Language resources are replaced once per change. Visible UI updates immediately,
  off-screen cards update in batches, and a new Auto option follows supported Windows
  display languages.
- Selection drag now scrolls slowly near the top and bottom edges, accepts mouse-wheel
  scrolling at the same time, and keeps off-screen cards in the range.
- Messenger filtering follows the source shown on the card. A filename containing a
  clear valid date takes title priority over image metadata or OCR.
- Messenger settings use compact one-row switches, automatic favorites are enabled by
  default for new installs at three uses, and the product tagline is now
  `이야기 속, 흩어진 순간들을 한 곳에`.

### Stability and performance

- Sentory recycles a stale Discord accessibility worker once without restarting
  Discord. Full-screen screen sharing no longer leaves detection stuck at Connecting
  when the valid message list is marked `OFFSCREEN`.
- Discord's idle state no longer shows an unnecessary connection banner, while delayed
  outgoing links can refresh the accessibility root and wait up to 15 seconds for the
  actual message.
- LINE idle accessibility refresh runs away from the WPF UI thread. Confirmation and
  license windows no longer disable the native owner window, reducing taskbar warning
  sounds and restore delays.
- Card previews, site icons, and detail images use separate 384px, 64px, and 480px decode
  paths. Detail images are decoded only when their view is opened.
- Initial cloud sync waits eight seconds. Language, search, filter, sort, and tab input
  can cancel an active folder read and retry it after two quiet seconds.
- With a real 116-item library and 428.9MB of source images, tab handling measured about
  58–59ms and a previously shown tab settled in about 264–360ms. The Release test suite
  passed 869 tests.

### Download

Most Windows PCs should use `Sentory-win-x64-setup.exe`. Use
`Sentory-win-x64-portable.zip` if you prefer not to install the app, or an `arm64`
package on Windows on ARM. The binaries are not code-signed, so Windows may show an
Unknown Publisher or SmartScreen warning. The matching source is available in
`Sentory-1.5.0-source.zip` and from the `v1.5.0` tag.

### Known limitations

- Uploads selected through a messenger's `+` file picker are not guaranteed to be
  detected. Paste an image into the chat input or drop it from Explorer and send it.
- Detection may pause temporarily if a supported messenger changes its interface.
- A large WPF library may take time to build thumbnails for the first time; layout and
  controls remain available while images fill in.
- Final testing of the ARM64 package on a physical Windows on ARM device is still pending.
- The executables and installers are not code-signed.
