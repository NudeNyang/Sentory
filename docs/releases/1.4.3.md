# Sentory 1.4.3

Sentory 1.4.3은 Discord와 Sentory를 어떤 순서로 켜도 현재 Discord를 다시
확인합니다. 새로 켠 Discord에 접근성 실행 옵션이 빠져 있다면 약 1분을 기다리지
않고 바로 재시작 여부를 묻습니다. 감지 준비가 끝난 뒤에는 무거운 접근성 탐색도
멈춥니다.

## 실행 순서와 관계없는 자동 연결

- Discord를 먼저 켠 뒤 Sentory를 실행하거나, Sentory가 켜진 상태에서 Discord를
  껐다 켜도 새 프로세스를 찾아 연결 준비를 다시 시작합니다.
- 새 Discord 메인 프로세스가 나타나면 실제 실행 명령을 한 번만 확인합니다.
  접근성 옵션이 이미 있으면 재시작하지 않고 그대로 연결합니다.
- 재시작 뒤 새 PID가 나타나면 이전 연결 대기를 버리고 초기 확인을 곧바로 다시
  시작합니다. 새 Discord가 켜졌는데도 30초 대기에 남던 문제를 고쳤습니다.
- Discord가 로그인 중이거나 채팅방을 열지 않아 메시지 목록이 보이지 않을 때는
  재시작이 필요하다고 판단하지 않습니다. 확인 간격을 30초로 낮추고 채팅 화면이
  준비될 때까지 기다립니다.

## 15초 재시작 안내

- 새 Discord 프로세스의 실행 명령에 접근성 옵션이 없으면 메인 창을 찾는 즉시
  15초 재시작 안내를 띄웁니다.
- 안내창에는 `취소`와 `지금 재시작` 버튼이 함께 표시됩니다. 통화나 작성 중인
  메시지가 있다면 취소할 수 있고, 바로 연결하려면 기다리지 않고 재시작할 수
  있습니다.
- 안내창에서 재시작을 누르거나 15초가 지나면 메인 화면의 재시작 배너도 바로
  사라지고 연결 준비 상태로 바뀝니다. 재시작에 실패하면 배너를 다시 보여 줍니다.
- 자동 안내를 취소하고 메인 배너에서 `나중에`를 눌러도 작은
  `Discord 재연결 필요` 상태는 남습니다.
- 같은 Discord 프로세스에는 한 번만 묻습니다. 취소한 뒤에는 설정의 재연결
  버튼을 직접 사용할 수 있으며, Discord를 새로 실행하면 실행 옵션을 다시
  확인합니다.

## 연결 후 동작과 상태 표시

- 감지 준비가 끝나면 Discord 접근성 트리 탐색을 중단합니다. 평소에는 현재
  Discord 프로세스가 끝나기를 기다리면서 10초마다 PID만 확인합니다.
- 실행 명령은 새 PID가 나타날 때 한 번만 읽습니다. Discord가 종료되면 감시는
  즉시 깨어나지만, 사용자가 다시 실행하기 전에는 Sentory가 Discord를 마음대로
  켜지 않습니다.
- 트레이에서 전체 감지를 일시정지하거나 다시 시작하면 이미 열린 설정창과 나중에
  연 설정창의 Discord·카카오톡 상태도 바로 같은 값으로 바뀝니다.

## 다운로드

대부분의 Windows PC에서는 `Sentory-win-x64-setup.exe`를 받으면 됩니다. 설치하지
않고 사용하려면 `Sentory-win-x64-portable.zip`을 완전히 푼 뒤 `Sentory.exe`를
실행해 주세요. Windows on ARM 사용자는 이름에 `arm64`가 포함된 파일을 선택해
주세요.

현재 파일에는 코드 서명이 적용되지 않았습니다. Windows에서 알 수 없는 게시자나
SmartScreen 경고가 나타날 수 있습니다. 공식 Release에서 받은 파일인지
확인하고, 필요하면 함께 제공되는 `.sha256` 파일과 대조해 주세요.

이 Release의 실행 파일에 대응하는 소스는 `Sentory-1.4.3-source.zip`과
`v1.4.3` 태그에서 받을 수 있습니다.

## 알려진 제한 사항

- Discord의 `+` 버튼을 이용한 파일 선택 업로드는 아직 감지를 보장하지 않습니다.
  사진은 채팅 입력창에 Ctrl+V로 붙여넣은 뒤 전송해 주세요.
- Discord 또는 카카오톡의 화면 구조가 바뀌면 감지가 잠시 멈출 수 있습니다.
- ARM64 패키지는 실제 Windows on ARM 장치에서 최종 검수가 남아 있습니다.
- 실행 파일과 설치 프로그램에는 코드 서명이 적용되지 않았습니다.

## English

Sentory 1.4.3 reconnects detection against the current Discord process regardless of
which app starts first. If a newly started Discord process is missing the accessibility
argument, Sentory shows the 15-second restart prompt as soon as the main window appears
instead of interrupting you about a minute later. Expensive accessibility scans stop
after detection becomes ready.

### Automatic connection regardless of startup order

- Sentory detects a new Discord process when Discord starts first or is closed and
  reopened while Sentory is running.
- Sentory reads the actual command line once for each new main process. A process that
  already has the accessibility argument continues without a restart prompt.
- When a new PID appears after a restart, Sentory discards the previous connection wait
  and starts a fresh warmup burst instead of falling into an extra 30-second delay.
- If Discord is still signing in or no chat is open, Sentory keeps a low-frequency
  30-second retry alive and returns to Ready when the chat becomes available.

### 15-second restart prompt

- If the new Discord process is missing the accessibility argument, the restart prompt
  appears as soon as its main window is found.
- The prompt includes both Cancel and Restart now. Cancel protects an active call or
  draft, while Restart now skips the countdown.
- Starting the restart hides the main repair banner immediately and switches it to the
  connecting status. The banner returns only if Discord could not be restarted.
- Choosing Later on the main banner keeps a compact Discord reconnect required status
  visible after the automatic prompt is canceled.
- The prompt appears only once per Discord process. A canceled restart remains available
  from Settings, and starting a new Discord process triggers a fresh connection check.

### Lightweight monitoring after connection

- Once detection is ready, Sentory stops walking the Discord accessibility tree. It
  waits on the current process exit event and keeps the existing 10-second PID check as
  a fallback.
- The process command line is read only once per new PID. Closing Discord wakes the
  monitor immediately, but Sentory does not launch it again until the user starts it.
- Pausing or resuming all detection from the tray now updates both open and newly opened
  Settings windows without changing each messenger's saved enabled state.

### Download

Most Windows PCs should use `Sentory-win-x64-setup.exe`. Use
`Sentory-win-x64-portable.zip` if you prefer not to install the app, or an `arm64`
package on Windows on ARM. The binaries are not code-signed, so Windows may show an
Unknown Publisher or SmartScreen warning. The matching source is available in
`Sentory-1.4.3-source.zip` and from the `v1.4.3` tag.

### Known limitations

- Uploads selected through Discord's `+` button are not guaranteed to be detected. Paste
  images into the chat input with Ctrl+V and send them instead.
- Detection may pause temporarily if Discord or KakaoTalk changes its interface.
- Final testing of the ARM64 package on a physical Windows on ARM device is still pending.
- The executables and installers are not code-signed.
