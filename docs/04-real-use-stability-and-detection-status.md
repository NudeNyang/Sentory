# 실사용 안정성 및 감지 상태 마감

## 적용 범위

Discord 감지 워커와 화면 상태 표시를 다음 기준으로 보강했다.

- Discord 채널 제목이나 창 핸들이 바뀌면 기존 대상 캐시를 폐기하고 다시 찾는다.
- Discord 재시작 뒤에는 이전 후보를 취소하고 새 창을 기준으로 감지 준비를 다시 수행한다.
- 감지 워커가 비정상 종료되면 한 번의 복구 작업만 시작하며, 복구가 끝나면 준비 완료 상태로 돌아간다.
- 링크와 사진 후보는 최대 8개까지만 동시에 처리하고, 같은 URL이나 사진 해시는 중복 후보로 만들지 않는다.
- 붙여넣기만 한 경우, Shift+Enter, 입력 삭제 및 전송 취소, Discord가 아닌 앱의 입력은 저장 확정으로 처리하지 않는다.
- 카카오톡의 기존 붙여넣기 감지 방식은 변경하지 않고 전체 회귀 테스트로 보호한다.

## 사용자에게 표시되는 Discord 상태

보관함 상단과 트레이 빠른 설정에서 같은 문구와 의미 색상을 사용한다. 색상만으로 상태를 구분하지 않도록 문구도 항상 함께 표시한다.

| 상태 | 의미 |
| --- | --- |
| 연결 준비 중 | Discord 창과 접근성 대상 목록을 찾고 있다. |
| 감지 준비 완료 | 링크와 사진 전송 확인을 받을 준비가 끝났다. |
| Discord 재연결 필요 | Discord 접근성 구조를 읽을 수 없어 다시 연결해야 한다. |
| 워커 복구 중 | 종료되거나 끊긴 감지 워커를 다시 시작하고 있다. |

라이트 모드와 다크 모드는 각각 별도의 의미 색상을 사용하며 두 테마에서 문구, 상태점, 배경 대비를 확인한다.

## 자동 검증

2026-07-19 기준 전체 138개 테스트가 통과하도록 구성했다.

- Core 21개
- Platform Windows 59개
- Diagnostics 15개
- Infrastructure 43개

안정성 관련 자동 검증에는 다음 항목이 포함된다.

- Discord 채널 제목, 렌더러 창, 프로세스가 달라졌을 때 대상 캐시 무효화
- 붙여넣기만 한 URL과 Shift+Enter 후보를 전송 완료로 확정하지 않음
- 삭제하거나 수정한 URL 및 다른 Discord 문맥의 사진 후보 취소
- Discord가 아닌 프로세스와 잘못된 렌더러 창 차단
- 100개 워커 요청을 한 프로세스에서 순서대로 처리
- 저장소를 반복해서 다시 열며 링크와 사진 30개를 연속 저장한 뒤
  데이터와 사진 파일이 모두 유지되는지 확인
- 연결 준비, 준비 완료, 복구 중, 재연결 필요 상태 분류와 중복 상태 알림 억제
- 복합 런타임의 상태 이벤트 및 복구 요청 전달
- 카카오톡 창, 입력창, 사진 확인 문맥 회귀 테스트

다음 명령으로 빌드와 전체 자동 검증을 한 번에 실행할 수 있다.

```powershell
.\scripts\Test-RealUseStability.ps1
```

## 실제 실행 검수

2026-07-19에 새 빌드를 실행해 다음을 확인했다.

- 라이트 모드와 다크 모드 보관함에서 `Discord 감지 · 감지 준비 완료` 문구와 의미 색상이 표시됐다.
- 상태 문구가 Windows 접근성 트리에도 노출됐다.
- 실행 중인 Discord 감지 워커를 강제로 종료한 뒤 `worker-recovery-started`가 기록됐다.
- 약 3초 뒤 새 워커가 `target-cache-warmed`로 준비를 마치고 상태가 `감지 준비 완료`로 복귀했다.

실제 메시지 전송이 필요한 아래 항목은 Discord 비공개 작업장과
카카오톡 테스트 채팅에서 묶어서 확인한다. 자동 테스트 통과와 별개로,
배포 후보를 바꿀 때마다 한 번씩 확인한다.

1. [ ] Discord 채널 이동 뒤 URL과 사진을 연속 전송한다.
2. [ ] 붙여넣기만 한 뒤 취소하고, Shift+Enter 뒤 취소해 저장되지 않는지 확인한다.
3. [ ] Discord를 종료하고 다시 실행한 뒤 URL과 사진을 각각 전송한다.
4. [ ] Discord 이외의 앱에 같은 URL과 사진을 붙여넣어 저장되지 않는지 확인한다.
5. [ ] 카카오톡 채팅 입력창에서 URL과 사진을 붙여넣어 기존처럼 즉시 저장되는지 확인한다.
6. [ ] 카카오톡 검색창이나 다른 앱에서는 같은 동작이 저장되지 않는지 확인한다.
7. [ ] Sentory를 2시간 이상 실행한 뒤 감지 상태와 진단 로그에 반복 오류가 없는지 확인한다.

장시간 안정성은 100개 연속 워커 요청 테스트와 워커 강제 복구로 기본 경로를 검증했다. 실제 장시간 실행은 이후 일반 사용 중 진단 로그의 반복 오류, 워커 재시작 횟수, 누락 여부를 함께 관찰한다.
